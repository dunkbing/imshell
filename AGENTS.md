# imshell – agent guide

A Dear ImGui toolkit for cross-platform apps, grown while building DearSQL (its first host, where it is the `external/imshell` submodule). The README says what it has and how a host uses it; this file is how to work on it.

- Everything is in namespace `imshell` (themes in `imshell::Theme`); no host names (no `dearsql`, no `DEARSQL_*` macros) inside the library. A host-specific need is a hook the host fills, not an include of the host.
- Dear ImGui and what is built on it are submodules in `external/` (imgui on the docking branch, imgui_test_engine, imgui_rich_md, imgui-node-editor), each defaulting a cache variable (`IMSHELL_IMGUI_DIR`, `IMSHELL_TEST_ENGINE_DIR`, `IMSHELL_RICH_MD_DIR`, `IMSHELL_NODE_EDITOR_DIR`) a host may point at its own copy; bump one only with DearSQL building against it. Never compile Dear ImGui core here: the host builds it once from `IMSHELL_IMGUI_DIR` (imshell compiles only the backends). Two copies split ImGui's global context silently.
- Widgets draw with `Theme::Current()`; the host sets it when its theme changes.
- Components (`include/imshell/components.hpp`, `src/components.cpp`, namespace `imshell::ui`) are a separate opt-in target, `imshell::components`: core never includes them. a new one goes into the gallery (`examples/gallery`, also the site demo) and `tests/components_test.cpp` (fails on a duplicate item id via the test engine item hook).
- The editor (`include/imshell/editor.hpp`, `src/editor.cpp`, `imshell::TextEditor`) is another opt-in target, `imshell::editor`, moved from DearSQL. it knows no language: highlighting, completion, comment prefix and indent words are hooks the host sets. `tests/editor_test.cpp` drives it with imgui input events on a bare context (the chords with `ConfigMacOSXBehaviors` off); a new key or hook gets a check there.
- Markdown (`include/imshell/markdown.hpp`, `src/markdown.cpp`, namespace `imshell::Markdown`) is an opt-in target too, `imshell::markdown`, over imgui_rich_md (the submodule, `IMSHELL_RICH_MD_DIR`, or a host's `imgui_rich_md` target added first); without one the target and its test do not exist. it links `imshell::editor` for code blocks; fonts, the highlighter per language and code-block buttons are options the host fills. `tests/markdown_test.cpp` runs on a bare context that plays the renderer backend for the atlas textures.
- The node editor (`include/imshell/node_editor.hpp`, `src/node_editor.cpp`) is an opt-in target too, `imshell::node_editor`: imgui-node-editor compiled from its submodule, with `NodeEditor::ApplyStyle()` / `ApplyColors()` theming it; the editor API stays `ax::NodeEditor`. `tests/node_editor_test.cpp` draws a graph on a bare context.
- The site (`site/`): astro + tailwind v4, styled like dearsql.dev (jetbrains mono like the apps, a latin subset without ligatures; its palette, light and dark from the os). `/docs/<page>` renders the repo's own `docs/*.md` (order, titles and descriptions from `docs/README.md`'s link list; a remark plugin in `astro.config.ts` turns `page.md` links into routes), so docs are edited only in `docs/`. `site/build.sh` compiles the gallery to wasm into `public/gallery` (git-ignored) and runs `astro build` into `site/dist`. `IMSHELL_SITE_BASE` sets a sub-path. hosted on cloudflare pages (project `imshell`, `imshell.pages.dev`), built from the repo (root `site/`, build command `bash cloudflare-build.sh`, which fetches pinned emscripten, cmake and ninja and the imgui submodule, then runs `build.sh`). the landing page's performance section reads `src/data/benchmarks.json`, written by `site/bench.sh <release build dir>` on a mac with an unlocked screen (imshell draws nothing unfocused); re-run it rather than editing numbers, and never tailwind `text-base` (the palette has a `base` colour: it paints text in the background colour). a feature on the landing page or a component in the list changes with the code.
- Headers in `include/imshell/`, sources in `src/`, vendored single headers in `third_party/` (private include). Add a source to `CMakeLists.txt` when you add one.
- C++20. Comments short and lowercase. Keep it small: something moves in when a host needs it, not before.
- A change to what a host sees (a function, a header, a CMake function) updates `README.md` and the matching page in `docs/` (and the table in `docs/platforms.md` when a platform gains or differs) in the same commit.
- Build on its own (`docs/getting-started.md`, "Building imshell on its own": `vcpkg.json`, `IMSHELL_BUILD_EXAMPLES`, `IMSHELL_BUILD_TESTS`, then `ctest`, which runs the touch test and hello's probe in a real window), and through a host (DearSQL: `./scripts/build`, then `./build/ui_tests -nopause`). The probe checks print `probe: ok` or `probe: FAILED:`; add a check there when a shell behaviour can be driven from imgui.
- Changes land through a pull request, never a push to `main`. Commits: short one-line subject, no trailers or attribution lines.

## Platform shell

- Shared by every shell (`src/app.cpp`): `DataDir`, `detail::useIniFile` (each `create()` calls it after `ImGui::CreateContext`), and `Run` (a static `App` so android keeps it across a recreated activity; not on ios). `closeRequested` is a glfw close callback in `glfw_loop.hpp` and gtk's `close-request` on linux. The linux close button drawn by imshell asks the delegate too. haptics: `src/apple/haptics.mm` (uikit generators, appkit's feedback performer), java `haptic(int)` on android (the enum's order), `src/haptics_none.cpp` elsewhere. `src/alert.cpp` is the alert queue (`alert.hpp`), moved from DearSQL. `src/fonts.cpp` (`AddFont`, the mapped system cjk font) and the file dialogs (`src/file_dialog_nfd.cpp` on desktops, nfd init and quit around each dialog; `src/ios/file_dialog.mm`, `src/android/file_dialog.cpp` over `PickFile`) also came from DearSQL.

`imshell::App` (`include/imshell/app.hpp`) is the window, the graphics backend, the imgui platform and renderer backends, the frame loop and input; the host implements `imshell::Delegate`. One implementation per platform under `src/<platform>/`:

- macOS (`src/macos/`): glfw window without a gl context, metal through a `CAMetalLayer` (`metal_backend.mm`), drag-and-drop and Finder's open-file event to `Delegate::openFile`. The loop idles after 2 s without input (waits grow to 0.2 s), never renders unfocused (`nextDrawable` blocks in the background), and sleeps out the frame with vsync off.
- iOS (`src/ios/`): uikit runs the loop. it idles like the desktops: `settle()` after each frame pauses the `MTKView` (`enableSetNeedsDisplay`) 2 s after the last busy frame, and `wake()` unpauses it from `ImShellWindow sendEvent:` (every touch, key, hover), text input, a resize, the keyboard and `requestFrames()`; a 1 s timer redraws a paused view. `RunUIKit` starts a scene whose root is a `UINavigationController` around the host's controller class (`ImShellViewController` or a subclass; the bar stays hidden unless the subclass shows it). The controller owns `ImShellView` (an `MTKView` adopting `UITextInput` over a one-position document: insertText and deleteBackward become imgui chars and keys, the space-bar trackpad becomes arrows), the gestures (a finger touch is held back until it is a tap, a press-and-drag on a resize or text cursor, a pan that scrolls and coasts, or a long press that right-clicks or shows the edit menu over text) and the keyboard inset. `create()` must run inside the controller's `loadView`, after super: the view exists then. Not checkable from here: real touches; the simulator shows launch, layout, the keyboard and the bar.
- Windows (glfw + dx11) and Linux (gtk4 + opengl): still in DearSQL, moving next.
- Android (`src/android/app.cpp`): NativeActivity through the ndk's `android_native_app_glue` (compiled into imshell; `-u ANativeActivity_onCreate` keeps its entry point in the host's shared library). The host's `android_main` calls `SetAndroidApp` and then `create()` pumps the looper until the window exists. A recreated activity (a configuration change `configChanges` cannot cover) keeps the process: `run()` asks java `isChangingConfigurations()` on destroy, releases the egl context and detaches the glue thread, and the next `SetAndroidApp` re-attaches (new looper, jni env, window; same imgui and egl contexts). EGL + GLES 3 with imgui's opengl3 renderer; imgui coordinates are dp (`DisplayFramebufferScale` = density), and the activity is edge to edge on every version (target api 36): `ImShellActivity.windowInsets` gives the bars, cutouts and keyboard: the status bar becomes the safe area (`SafeArea()`, `Platform_GetWindowWorkAreaInsets`), the rest shrinks the imgui display (popups clamp to it) (the draw data's `DisplayPos`/`DisplaySize` still cover the window); the bar icons follow the theme's brightness (`setLightBars`). Touch is the shared engine (`src/touch.cpp`, also behind the ios gesture recognizers; tested by `tests/touch_test.cpp` on a bare imgui context, `IMSHELL_BUILD_TESTS`) fed with raw motion events, as the web shell feeds it the canvas's touch events (pending until a frame has hovered the spot, scroll with fling, a press-drag on a resize cursor, or on a widget after a 150 ms hold; a long press over a text cursor double-clicks to select the word and opens the floating `ActionMode` text toolbar, whose picks come back as ctrl chords, elsewhere it right-clicks); keys go through `imgui_impl_android`. Java wakes the looper through a native `wake()` registered with `RegisterNatives` (toolbar picks, picked files, inset changes). What the ndk cannot do (characters, soft keyboard (an invisible `Editor` view whose `InputConnection` edits a buffer of what was typed since the last tap; each edit goes to imgui as the diff, backspaces then text, through the ordered char queue with negative codes for backspace, delete and enter), clipboard, document picker, text toolbar, haptics) is `android/io/imshell/ImShellActivity.java`, called over jni from the glue thread. The loop runs at vsync for input, `wantsFrames()` or animation (touch, fling, queued input events, an open picker) and sleeps when idle until `requestFrames()` wakes the looper (`ALooper_wake`), with a 1 s heartbeat like the desktop loops. `cmake/ImShellAndroid.cmake` + `cmake/android/apk.sh` pack the apk without gradle; `imshell_hello` builds as an apk with `IMSHELL_BUILD_EXAMPLES` (checked on an api 36 emulator: taps, popups, insets).
- Web (`src/web/app.cpp`, `if(EMSCRIPTEN)` before `UNIX` in CMake): emscripten's `contrib.glfw3` port on a full-page canvas, imgui's opengl3 backend on webgl2, `emscripten_set_main_loop` as the loop (`run()` never returns). single threaded on purpose (any static host). a frame identical to the last is not drawn: the canvas keeps its image. no native views or file dialogs yet. build with `emcmake` (docs/getting-started.md); check in headless chrome with `--use-angle=swiftshader`.

Title bar (`title_bar.hpp`): the bar is an ImGui window over the strip. A click reaches ImGui first; `EndTitleBar()` decides after the frame whether it hit a widget, and only a click on empty bar space starts the native drag (`performWindowDragWithEvent:` with the mouse-down a local event monitor kept, after `present()`, skipped when the button is already up) or the double-click action (`AppleActionOnDoubleClick`). This way nothing answers a hit test from last frame's rectangles. `IMSHELL_HELLO_PROBE=1 ./imshell_hello` checks both paths with ImGui input: a double-click on empty bar space zooms, a click on the bar's button presses it.

Native views (`src/apple/native_view.mm`, both Apple shells, ARC): an entry per ImGui id holds a clip view and the host's view. `NativeView()` records the item rect and its part inside the window's clip rect; `detail::placeNativeViews()`, which each shell calls after rendering, sets the frames, hides entries not drawn this frame or covered by a root window displayed above the entry's dock tree (`FindWindowDisplayIndex`), and frees entries unused for 3 s. On macOS the views live in a flipped overlay above the Metal view that passes clicks through except over a view, and a mouse-down outside the overlay gives the keyboard back to GLFW's content view; on iOS a touch on `ImShellView` makes it first responder again. `imshell_hello` shows a native text field and date picker; its probe checks the field is placed (16,127 240x22) and hidden under a popup.

Windows (`src/windows/`): GLFW + Direct3D 11 (`dx11_backend.*`); `app.cpp` subclasses GLFW's window procedure for the custom frame (`WM_NCCALCSIZE`, `WM_NCHITTEST` with `HTMAXBUTTON` for snap layouts, `WM_GETMINMAXINFO`), draws the caption buttons in `BeginTitleBar`, and starts the system move loop (`WM_NCLBUTTONDOWN` / `HTCAPTION`) after the frame. ImGui coordinates are pixels there. The run loop (`src/glfw_loop.hpp`) and native views' layout (`src/native_view.cpp`) are shared; each platform supplies `nativeAttach` / `nativePlace` / `nativeSetHidden` / `nativeRemove`. Windows builds only on CI (the DearSQL `windows.yml` workflow, dispatched on a branch).

Objective-C classes cannot live in a C++ namespace and their names are global: close `namespace imshell` around them and prefix them `ImShell`. `.mm` files compile as C++ (no `enable_language(OBJCXX)`: mixed with a host that does not enable it, generation fails).
